# ML Transformer Health Service — Integration Contract

**Document Purpose:** Defines the strict technical contract between the Machine Learning Transformer Health Service and the downstream Grid-Level Risk Engine for the Power Grid AI hackathon platform.

---

## 1. Architectural Role & Boundary

The Transformer Health Service is an autonomous, physical asset-level diagnostics service. It operates solely on Dissolved Gas Analysis (DGA) chemical chromatography time-series telemetry from transformer oil sensors.

## 2. Scope Boundaries & Non-Inputs

To maintain machine learning rigor and avoid synthetic data leakage, the following data boundaries are explicitly enforced:

### Current ML Inputs (Active)
- **Oil Chromatography Telemetry:** 420-step time series of:
  - Hydrogen ($H_2$)
  - Carbon Monoxide ($CO$)
  - Ethylene ($C_2H_4$)
  - Acetylene ($C_2H_2$)

### Downstream Integrations (NOT inputs to the ML service)
The downstream Grid-Level Risk Engine can fuse our ML outputs with external context layers:
- ⛈️ **Weather Risk:** Real-time convective storm fronts, lightning strike density, high ambient temperatures, wind gusts.
- 🗺️ **Geographic Information (GIS):** Substation coordinates, elevation, flood-zone overlays, proximity to vegetation or wildfire zones.
- ⚡ **Grid Topology & Power Flow:** N-1 contingency status, transmission bus connections, current loading (MVA), branch impedances.
- 🏥 **Transformer Criticality:** Hospital/data center load priority, customer count served, replacement equipment lead time.
- 🚚 **Logistics & Crew Availability:** Maintenance depot proximity, spare transformer inventory, field crew shift status.

> **CRITICAL NOTICE:** None of the above grid/weather parameters are passed into the DGA ML model. They are combined downstream with the transformer health output generated by this microservice.

## 3. Microservice API Specifications

### Service Endpoint
- **Base URL:** `http://localhost:8000` (or Docker container alias)
- **Protocol:** HTTP REST / JSON

### 3.1 Health Check: `GET /health`
Verifies microservice operational status and confirms all models are loaded in memory.

**Response `200 OK`:**
```json
{
  "status": "healthy",
  "models_loaded": true,
  "uptime_seconds": 124.5,
  "loaded_models": {
    "fdd_classifier": "HistGradientBoostingClassifier",
    "rul_regressor": "HistGradientBoostingRegressor",
    "scaler": "StandardScaler"
  }
}
```

---

### 3.2 Single Transformer Inference: `POST /predict`
Processes a 420-step DGA time-series array for one transformer and returns comprehensive diagnostics.

**Request Body:**
```json
{
  "asset_id": "2_trans_939.csv",
  "data": [
    { "H2": 0.001, "CO": 0.004, "C2H4": 0.003, "C2H2": 0.0001 },
    ... 420 items ...
  ]
}
```

**Response `200 OK`:**
```json
{
  "asset_id": "2_trans_939.csv",
  "predicted_fault": "Class 4: High-Energy Electrical Arcing / Flashover",
  "fault_probability": 0.9998,
  "fault_probabilities": {
    "class_1": 0.0002,
    "class_2": 0.0,
    "class_3": 0.0,
    "class_4": 0.9998
  },
  "predicted_rul": 417.27,
  "anomaly_score": 51.08,
  "risk_score": 85.12,
  "risk_category": "CRITICAL",
  "recommended_action": "Immediate inspection and maintenance recommended. Prioritize this transformer for engineering review.",
  "top_risk_factors": [
    "Predicted Class 4 arcing pattern (confidence 100.0%)",
    "Critically depleted remaining useful life (approx. 417 cycles)",

}
```

---

### 3.3 Batch Transformer Inference: `POST /predict/batch`
Enables parallel batch inference for up to 1,000 transformers in a single API round-trip.

**Request Body:**
```json
{
  "transformers": [
    { "asset_id": "2_trans_939.csv", "data": [ ... ] },
    { "asset_id": "2_trans_1672.csv", "data": [ ... ] }
  ]
}
```

**Response `200 OK`:**
```json
{
  "total_processed": 2,
  "results": [ ... array of prediction objects ... ]
}
```

## 4. Downstream Grid Integration Example (Python)

Below is an example illustrating how downstream grid engineers can combine the transformer ML output with weather and topology risks:

```python
import requests

# 1. Fetch ML Asset Health
ml_resp = requests.post(
    "http://localhost:8000/predict",
    json={"asset_id": "2_trans_939.csv", "data": dga_time_series}
).json()

asset_risk = ml_resp["risk_score"]        # e.g., 85.12 (out of 100)
predicted_fault = ml_resp["predicted_fault"] # e.g., Class 4 Arcing

# 2. Query Downstream External Modules (Weather, Grid Criticality)
weather_storm_risk = get_substation_weather_risk(substation_id="SUB_42") # e.g., 90.0 (Severe storm / lightning)
bus_criticality = get_grid_topology_criticality(bus_id="BUS_138KV_04")    # e.g., 1.5 (Supplies city hospital)

# 3. Compute Holistic Grid Operational Impact
grid_composite_risk = (0.50 * asset_risk + 0.30 * weather_storm_risk) * bus_criticality

print(f"Holistic Grid Risk Score: {grid_composite_risk:.2f}")
if grid_composite_risk > 100:
    dispatch_mobile_substation_and_reroute_feeders(substation_id="SUB_42")
```
